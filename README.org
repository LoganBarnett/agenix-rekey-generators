Secret generators for [[https://github.com/oddlama/agenix-rekey][agenix-rekey]].  Each one fills ~age.generators.<name>~.  A
secret names it with ~generator.script~ and ~agenix rekey generate~ produces the
value.  They work on NixOS, nix-darwin, and Home Manager alike.

* Using the generators

Add the flake as an input and import the module beside agenix-rekey's own.

#+begin_src nix :exports code
{
  inputs.agenix-rekey-generators.url =
    "github:LoganBarnett/agenix-rekey-generators";
  # ...
  modules = [
    agenix-rekey.nixosModules.default
    agenix-rekey-generators.nixosModules.default
  ];
}
#+end_src

~darwinModules.default~ and ~homeManagerModules.default~ are the same module.  A
flake that wants one generator without the module takes it from
~lib.generators~.

A secret then names a generator.  A generator that derives its value from
another secret lists that secret as a dependency.

#+begin_src nix :exports code
{
  age.secrets.ldap-root-pass.generator.script = "passphrase";
  age.secrets.ldap-root-pass-hashed.generator = {
    script = "slapd-hashed";
    dependencies = [ config.age.secrets.ldap-root-pass ];
  };
}
#+end_src

* Conventions

1. ~dependencies~ is a list.  A generator that takes one dependency reads the
   first.  A generator that takes many reads them in order.
2. A generator that needs more than its dependencies reads ~settings~ on the
   secret.  The table names the keys.
3. A generator that writes a file beside the secret, such as a public key, hands
   it to ~gitAdd~ so ~--add-to-git~ covers it.  ~gitAdd~ is
   [[https://github.com/oddlama/agenix-rekey/pull/165][agenix-rekey pull request 165]].  Until it merges, those generators need
   [[https://github.com/LoganBarnett/agenix-rekey][the fork]] that carries it.
4. ~hex~ and ~base64~ replace the generators agenix-rekey ships.  Without
   ~settings.length~ they produce the same output.
5. A secret a service reads as an ~EnvironmentFile~ belongs in that unit's
   ~restartTriggers~.

** TLS

~tls-ca-root~ reads ~settings.tls~ with ~domain~, ~validity~ in days, and
~subject~ with ~country~, ~state~, ~location~, ~organization~, and
~organizational-unit~.  The root is name constrained to ~domain~ and cannot sign
an intermediate.

~tls-signed-certificate~ reads ~settings.fqdn~ and ~settings.root-certificate~,
the root's ~age.secrets~ entry, and lists that entry as its one dependency.  The
~.srl~ file tracks the serial numbers the root has issued and is checked in.
